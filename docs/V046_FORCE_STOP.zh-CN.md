# v0.4.6 ComfyUI 强制关闭

v0.4.6 在设备页补充“强制关闭”恢复路径，用于 ComfyUI 仍占用 GPU / 内存、普通关闭却因为缺少 Panel 进程记录而无法执行的情况。

## 界面行为

- ComfyUI 由当前 Panel 启动并且进程记录有效时，设备页继续显示普通“关闭”。
- 如果没有 Panel 进程记录，但系统能够安全识别当前 ComfyUI 监听进程，原来的红色“关闭”按钮会改成“强制关闭”。
- 如果 ComfyUI API 已经无响应，只要监听进程仍能被安全识别，“强制关闭”仍可使用。

## 安全边界

强制关闭不会按进程名搜索并结束任意 `python.exe`。只有同时满足以下条件时才允许执行：

1. 当前配置的 ComfyUI 端口上只能得到唯一匹配的监听进程；
2. 进程可执行文件与 `[comfyui.control] start_command` 中配置的 Python 一致；
3. Python 入口与当前配置的 ComfyUI `main.py` 一致；
4. 进程工作目录与当前配置的 ComfyUI 工作目录一致。

`--use-sage-attention` 这类可选启动参数不再参与强制关闭的兜底身份判断。这样即使用户修改了 `start_command`，修改前已经启动、仍然卡住的旧 ComfyUI 进程也可以继续被安全识别并强制关闭。

如果可执行文件、Python 入口、工作目录或监听进程无法唯一、安全确认，Panel 会拒绝强制关闭。

强制关闭会结束已验证的 ComfyUI 主进程及其已确认子进程，并使当前未完成任务进入中断状态。普通“关闭”的原有安全规则不变。
