# Comfy Remote v0.2 UI / Visual Specification

本文档是 Comfy Remote v0.2 移动端界面的视觉与交互基线。后续新增页面、工作流适配和功能入口应优先复用这里定义的信息层级与组件语义，不应为单个工作流重新发明一套 UI。

## 1. 产品与视觉定位

产品显示名称固定为 **Comfy Remote**。

Comfy Remote 是手机优先的 ComfyUI 远程创作端，不是把 ComfyUI 节点编辑器搬到手机，也不是服务器监控大屏。工作流在 ComfyUI 中完成复杂配置，手机端只暴露创作所需的输入、基础生成设置、少量高级参数、任务结果和工作站控制。

视觉关键词：

- 专业、克制、轻量；
- 以创作内容和结果为主，不以技术参数为主；
- 深色背景 + 单一荧光黄绿色强调色；
- 少套框、少解释、少重复；
- 手机单列优先，桌面只放宽，不重新设计 Dashboard。

## 2. 主信息架构

固定主导航：

- **创作**：工作流、参考素材、提示词、基础生成设置、生成；
- **任务**：运行状态、结果、再次生成、下载、详情；
- **设备**：ComfyUI / GPU / 显存 / 工作站控制。

右上角齿轮进入 **设置**。工作流管理属于设置，不占主导航。

主导航本身已经表达当前页面，因此创作、任务、设备页正文不重复显示同名大标题。设置、工作流管理等非主导航子页面仍保留页面标题。

任务页不设置额外刷新按钮。点击“任务”标签即加载/刷新任务；已在任务页时再次点击同样刷新。

## 3. 色彩 Token

```css
--bg: #0e100d;
--surface-1: #161914;
--surface-2: #1d211a;
--surface-3: #242920;
--border: #30362b;
--border-soft: #252a22;

--text-primary: #f4f6ef;
--text-secondary: #b7bcaf;
--text-tertiary: #7e8578;

--accent: #c8f36a;
--accent-hover: #d4f985;
--accent-soft: rgba(200, 243, 106, .10);

--danger: #ff7a70;
--warning: #e9c568;
--success: #9fe4ae;
```

Accent 只用于主操作、当前选择、在线状态、进度和关键数值，不大面积铺满卡片或页面。

## 4. 字体层级

使用系统无衬线字体优先：

```css
Inter, ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif
```

建议层级：

| 用途 | 字号 | 字重 |
| --- | ---: | ---: |
| 页面 / 子页面标题 | 24–26 px | 700 |
| 一级区块 | 16–18 px | 600 |
| 卡片主标题 | 15–16 px | 600 |
| 正文 | 14–15 px | 400 |
| 控件 | 14 px | 500–600 |
| 辅助信息 | 12–13 px | 400 |
| 标签 | 11–12 px | 500 |

避免把英文眉题、超小字号或超大粗体当成主要信息层级。

## 5. 间距、尺寸与圆角

- 页面左右边距：16 px；
- 大区块间距：24 px；
- 组件间距：8 / 12 / 16 px；
- 普通控件高度：44–48 px；
- 主按钮：约 52 px；
- Input / Button / 小卡片圆角：12 px；
- 大容器：16 px；
- Bottom Sheet 顶部：约 20 px；
- 只有状态 Tag / Pill 使用 999 px 圆角。

不要继续把所有控件做成大药丸，也不要大卡片套小卡片再套按钮。

## 6. 图标

统一使用线性 SVG：

- stroke 约 1.75–2 px；
- rounded cap / join；
- 不用 Emoji；
- 不混用 Unicode 几何符号和正式图标；
- 主要点击热区不小于约 44×44 px。

右上角设置齿轮视觉上无边框，但仍保留完整点击热区和轻微按压 / focus 反馈。

## 7. 文案原则

主界面常驻文字只保留四类：

1. 操作；
2. 当前数据；
3. 当前状态；
4. 用户必须知道的约束。

如果一句话只是解释界面本身，且控件位置、名称、禁用态已经能表达含义，则默认删除。

示例：

- 保留“首帧”“尾帧”，删除“镜头起点 · 可选”“镜头终点 · 可选”；
- 保留“提示词”，placeholder 使用“输入提示词……”；
- 删除工作流卡中的“视频 · 首尾帧生成”等重复类型说明；
- 负面提示词的“已使用默认值”属于真实状态，应保留；
- 错误、失败原因、上传进度、运行进度属于真实状态，应保留。

## 8. 统一创作信息层级

图片、视频以及后续 Generic Workflow 都遵循相同的主顺序：

1. 工作流；
2. 参考素材（工作流需要时）；
3. 提示词；
4. 负面提示词（工作流存在时）；
5. **生成设置**；
6. **高级设置**（工作流暴露高级参数时）；
7. 生成。

不同工作流可以缺少某个区块，但不应颠倒顺序。尤其不允许图片工作流出现“高级设置 → 生成设置”，而视频工作流使用相反顺序。

## 9. 工作流选择

工作流选择位于创作页一级入口，不放在高级设置中。

使用移动端 Bottom Sheet，而不是把原生大型 `<select>` 当主 UI。选择器只显示在创作页可见的工作流，使用用户设置的显示名称，隐藏内部 workflow ID。

工作流管理中的开关语义是 **“显示在创作页 / 隐藏”**，不是停用 ComfyUI 执行能力。点击应即时在前端反馈，并后台异步持久化；保存失败才回滚。

隐藏工作流不得破坏历史任务、工作流 ID 或历史任务的再次生成。

## 10. 参考素材

### FL2VA

显示两个清晰槽位：

- 首帧；
- 尾帧。

两者均可选，不重复写“可选”。上传后直接显示图片缩略图，并支持替换。

### Ref2VA

使用统一横向参考素材区域：

- 添加参考；
- 图片；
- 视频；
- 音频。

允许横向滚动。素材数量限制由工作流定义，当前 H3 Ref2VA 为最多 9 图 / 3 视频 / 3 音频。

### Generic 图片工作流

只显示工作流声明的图片、视频或音频输入，不因为 workflow JSON 中存在其他 literal input 就创建参考素材 UI。

## 11. 画幅规范

H3 固定画幅顺序：

1. 9:16；
2. 16:9；
3. 1:1；
4. 3:4；
5. 4:3；
6. 21:9；
7. 条件型参考画幅。

不在创作 UI 中提供 2:3 / 3:2。

FL2VA 最后增加 **参考图**：

- 首帧存在时优先使用首帧比例；
- 无首帧但有尾帧时使用尾帧比例；
- 首帧和尾帧都不存在时不可选择。

Ref2VA 最后依次增加：

- **参考图**：存在参考图 1 时可选；
- **参考视频**：存在参考视频 1 时可选。

条件型画幅永远放在固定比例之后，避免与常规比例混排。

## 12. 提示词与键盘状态

提示词是创作页视觉中心之一，但默认 textarea 不需要占据大半屏。移动端点击 Prompt 后进入专注输入状态：

- 导航和非核心区域可压缩；
- 保留必要参考素材信息；
- 生成动作始终可触达；
- 键盘关闭后恢复正常页面。

图片工作流的正面提示词与普通提示词使用同一视觉组件。负面提示词默认可折叠；如果工作流已有默认负面 Prompt，显示“已使用默认值”。

## 13. 生成设置

主页面只显示紧凑摘要：

- 视频示例：`9:16 · 10 秒 · 0.4 MP`；
- 图片示例：`3:4 · 1024×1365 · 4 张`。

点击“调整”进入 Bottom Sheet。

H3 画幅 / 时长 / MP 仅修改工作流允许的基础值。图片工作流的画幅快捷按钮转换为 width / height，并遵守节点 min / max / step；不能假设所有图片工作流都固定 1024。

## 14. 高级设置

只有工作流明确允许用户修改的高级参数才显示。典型内容：

- Sampler；
- Scheduler；
- Steps；
- Seed；
- CFG（仅工作流暴露时）。

导入工作流中的节点字面参数不应因为“存在”就默认变成手机高级参数。

## 15. 任务页

任务卡的职责是回答：

- 哪个工作流；
- 什么状态；
- 什么时候 / 用了多久；
- 核心生成参数；
- 结果是什么；
- 下一步操作。

任务卡 **不常驻展示 Prompt 正文**。Prompt 放入任务详情。

视频任务卡保留结果预览、再次生成、下载和详情。图片任务根据 artifact 数量显示单图、两列或 2×2 网格。

Sampler / Scheduler / Steps / Seed / Revision 等技术参数不占任务卡主视觉，放在任务详情。

## 16. 任务详情

任务详情包含：

- 工作流；
- 状态 / 时间 / 耗时；
- Prompt；
- 技术参数；
- 输入参数；
- 后续可扩展输入素材和输出文件信息。

Prompt 区域提供 **一键复制**。长 Prompt 在详情内滚动，不拉高整个任务列表。

## 17. 再次生成与生成现场恢复

当前“再次生成”负责恢复参数和保留素材引用。完整的 **Generation Reconstruction / 生成现场恢复** 是下一轮功能，不在本轮纯视觉收尾中伪装完成。

最终目标：

- Prompt / negative prompt 恢复；
- 生成设置恢复；
- 高级参数恢复；
- FL2VA 首帧 / 尾帧恢复可视化；
- Ref2VA 图片 / 视频 / 音频恢复可视化；
- retained 素材明确显示“沿用”；
- 支持替换和删除；
- 原文件丢失时显示明确状态。

图片素材可以直接恢复缩略图。参考视频第一版允许使用文件卡 + “沿用”，不要求依赖当前不稳定的视频缩略图链路。

## 18. 视频缩略图原则

视频缩略图不稳定应优先排查数据链路，而不是用 UI 重试动画掩盖：

- MP4 metadata / 首帧；
- Range 请求；
- 输出文件稳定时机；
- 浏览器媒体加载行为；
- 编码兼容性。

UI 可以有占位和失败态，但不应靠反复 `load()` 碰运气作为最终方案。

## 19. 设置

当前设置入口允许保留尚未实现的占位项，不作为本轮阻塞：

- 工作流：已实现；
- 连接：待完善；
- 日志与诊断：待完善；
- 关于：待完善。

后续“上传高清参考图自动压缩”属于全局输入预处理策略，适合进入常规设置，但需要先单独确定浏览器端 / Panel 端处理、最大尺寸、原图保留和工作流例外策略。

## 20. 设备与工作站控制

设备页首先服务远程创作：

- ComfyUI 是否在线；
- GPU / 显存；
- 启动 / 重启 / 关闭 ComfyUI。

Windows 工作站睡眠、系统重启、关机属于后续 Machine Lifecycle 能力。WoL、远程开机和机外唤醒需要机外能力，短期不进入 v0.2。

## 21. 响应式与兼容性

主要宽度基准：360 / 375 / 390 / 412 / 430 px。

必须避免：

- 横向溢出；
- 长工作流名遮挡；
- 按钮挤成两行；
- 固定高度截断 Prompt；
- 键盘出现后生成按钮不可触达。

目标浏览器：Chrome Android、Edge Android、Samsung Internet、Safari iOS。主要交互不依赖 hover。

## 22. 无障碍与交互最低要求

- 操作用 `<button>`；
- 图标按钮有 `aria-label`；
- Dialog / Bottom Sheet 有对应语义；
- 键盘 Escape 在桌面可关闭浮层；
- 颜色不是唯一状态表达；
- 主要点击区域不小于约 44 px；
- Progress 使用可访问的进度语义。

## 23. 三类基准适配

新 UI 设计至少同时自然容纳：

| 能力 | FL2VA | Ref2VA | WAI / 普通生图 |
| --- | --- | --- | --- |
| 主 Prompt | ✓ | ✓ | ✓ |
| 负面 Prompt | — | — | 可选 |
| 首帧 / 尾帧 | ✓ | — | — |
| 多参考图 | — | ✓ | 工作流决定 |
| 参考视频 / 音频 | — | ✓ | 工作流决定 |
| 画幅 | ✓ | ✓ | ✓ |
| 时长 | ✓ | ✓ | — |
| MP | ✓ | ✓ | — |
| Width / Height | — | — | ✓ |
| Batch | — | — | ✓ |
| 视频输出 | ✓ | ✓ | 工作流决定 |
| 图片输出 | — | — | ✓ |

只有这三类都能在同一信息层级下自然工作，才说明 UI 架构没有退回 H3 专用页面 + Generic 补丁。

## 24. 新功能设计检查清单

新增 UI 前先确认：

- 它是创作常用操作，还是低频设置？
- 是否已有现成组件可以表达？
- 是否重复解释了当前标签、标题或控件？
- 是否把技术实现细节暴露给普通用户？
- 图片和视频工作流能否使用相同信息层级？
- 360 px 手机是否仍然可用？
- 是否改变了本规范的固定顺序？如果改变，必须先更新规范再实现。
